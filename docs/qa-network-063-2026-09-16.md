## Startup and proxy outage

The nextctl profile gate passed in 37.533s against the exact ELF above. All five
invalid-startup cases exited without contacting the supplied external URL:
corrupt profile, missing proxy host, missing port, unsupported scheme, and API
unavailability. The API error case confirms that the failure path was exercised.

The deliberately direct control produced 35 origin requests, proving that the
instrumentation can detect direct access. The proxied browser remained running
through proxy authentication failure (407), bad gateway (502), and a stopped
proxy. During these stages it attempted HTTP/HTTPS/WS/WSS operations 18, 20, and
20 times respectively: **zero origin requests and zero direct requests** at
every stage, with the origin independently verified reachable throughout.
Top-level navigation was tested alongside background fetch/WebSocket traffic.

Report: `nextctl-profile-outage-063.jsonl`. This isolated origin-side gate uses
headless mode, `--no-sandbox`, and a test-certificate bypass; it is not desktop
or real-certificate acceptance. The STUN/TURN tests above do not use these
bypasses. No production endpoint or user profile is involved in this gate.
